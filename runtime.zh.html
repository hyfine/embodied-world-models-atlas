WM-1 / 潜动力学与基于模型的强化学习

PlaNet

预测与决策机制

都学潜动力学。差别在谁消费 rollout：PlaNet 当场比较动作，Dreamer 用想象轨迹训练 actor。

  • PlaNet — 决策时搜索
  • Dreamer — 训练时想象
文字版运行步骤
  1. 相机帧与上一动作
  2. RSSM 更新当前状态后验
  3. CEM 采样候选动作序列
  4. 逐序列想象潜状态并累计预测奖励
  5. 用高分序列迭代更新分布
  6. 规划器输出首步动作给环境

反馈与边界. 执行后以真实新图像修正状态，再规划；不将想象帧当作实际观测。

怎样验证. 六个像素控制仿真任务；图 4 分开检验搜索与数据采集。真实动力学规划是对照，不是部署输入。

WM-2 / 特征预测与对象表示

V-JEPA 2-AC

状态表示

I-JEPA 是表征学习的前史，不是可规划的动作转移系统；2-AC 加入机器人交互和独立规划器才有这个接口。

  • I-JEPA — 静态图像的表征目标
  • V-JEPA 2-AC — 动作条件预测与规划
文字版运行步骤

  2. 冻结编码器分别编码当前图与目标图
  3. CEM 提出末端动作候选

  6. 规划器给机械臂首步命令

反馈与边界. 真机完成指令后重新读取画面与末端状态；抓放实验按预设时刻更换目标图。

WM-3 / 视频生成与交互模拟

Genie

预测与决策机制

两者都能生成可游玩的未来，但输入动作的来源不同；“可玩”并不证明学到了真机的电机坐标。

  • Genie — 从视频推断潜动作
  • GameNGen — 游戏动作条件的帧预测
文字版运行步骤
  1. 将起始图像编码为离散视觉 token
  2. 玩家选择一个隐动作码
  3. 时空动力网络按历史与动作逐轮填充下一帧 token
  4. 视觉解码器渲染画面供玩家观察
  5. 将新 token 加入历史，等待下一动作

反馈与边界. 回传的是生成世界的历史和玩家输入，不是外部传感器；训练时推断动作的网络不在游玩回路里。

怎样验证. 平台游戏消融中，像素动作输入使 ΔPSNR 从 1.33 到 1.91，而 FVD 从 38.8 变为 40.1；记忆仅 16 帧，约每秒一帧。

WM-4 / 空间场景表示与演化

WonderWorld

状态表示

缩窄代表性：它们演示几何一致性。换视角仍能看到同一物体，不等于推它时能预测接触动力学。

  • WonderWorld — 持久分层场景
  • GEN3C — 相机轨迹与三维缓存
  • OccWorld — 时变占用对照，原索引 WM-5
文字版运行步骤
  1. 从单图初始化三层场景
  2. 用户给出新相机位姿和文字
  3. 渲染已知区域并补全新图像
  4. 用旧深度约束新深度，拟合分层面元
  5. 把几何加入场景并向用户渲染

反馈与边界. 用户看结果后再选位姿；保留的是几何，不是机器人策略。

怎样验证. 单块 A6000 每扩展场景 9.5 秒，并非每帧；背面未生成。

反馈与边界. 条件由数据或用户指定；没有驾驶策略出动作，检测器不反馈下一次观测。

怎样验证. nuScenes 纯相机 BEVFusion mAP 在 1× 训练时由 32.88 升至 35.40，2× 时只升 0.25；非驾驶安全评测。

WM-6 / 机器人的未来—动作耦合

DreamZero

未来与动作的耦合

以这两条不同的动作路径共同代表机器人预测控制。SuSIE 是级联例，不宜独自代表联合 WAM；仅把视频模型用于表征或造数据，也不能据此叫 WAM。

  • DreamZero — 联合生成未来与动作
  • SuSIE — 子目标图 → 目标条件策略
文字版运行步骤
  1. 观测、指令、本体状态
  2. 时序生成骨干
  3. 并行读出：未来 ∥ 动作
  4. 执行动作 → 接入真观测

反馈与边界. 推理端结合历史和新观测生成下一块，动作进入执行接口，预测视频用于建模或检查。它不等于在多个候选视频中显式运行 MPC；必须另计生成、通信和动作执行的延迟。

怎样验证. 比较基线时先分 AgiBot 与 DROID/Franka，再分任务进度与整回合成功。公开 DROID 检查点不等于复现论文中另一机型的权重、数据和结果。

EAI-1 / 语言、可行性与规划

ReKep

动作接口

保留高层选择这个共同问题，不合并输出：一个给约束，一个选已有技能；两者都不是直接从语言解码电机命令。

  • ReKep — 生成约束并求解
  • SayCan — 语言评分 × 技能可行性
文字版运行步骤
  1. 从 RGB-D 场景提出三维关键点，在图像上编号
  2. 指令与标点图输入 VLM，生成各阶段的终点约束和路径约束
  3. 读取当前点位和机械臂状态，检查是否需回退阶段
  4. 子目标求解器给出末端目标位姿，路径求解器给出到达它的运动
  5. 执行路径的一小段，由底层控制器驱动机械臂

反馈与边界. 动作后更新点位并重新求解，不是每次控制都重新询问 VLM。公开模拟器直接提供跟踪与碰撞几何，真机需另行感知。

怎样验证. 表 1：七项任务各十次，自动约束成功 31/70，人工约束 48/70。表 2 的受扰三项任务不是同一个分母；自动方案成功 8/30。

EAI-2 / 视觉语言动作基础模型

OpenVLA

动作接口

VLA 描述视觉、语言和动作接口，不规定动作必须离散。动作块长度与 token 连续/离散是两个问题。

  • OpenVLA — 自回归动作符号
  • π0 — 连续动作块与流匹配
文字版运行步骤
  1. 读取当前相机图像与自然语言任务
  2. 融合 DINOv2 与 SigLIP 的图块特征，映射至文本嵌入空间
  3. Llama 2 以视觉与指令为条件，逐维自回归生成动作词元
  4. 解码至区间中心，按目标数据集的分位数还原动作尺度
  5. 机器人执行一次末端运动与夹爪指令，再读取新图像

反馈与边界. 示范用于离线训练；Bridge 运行脚本在动作之间刷新观测。基础策略每次只看一张图，不预测未来图像，也不在线更新权重。

怎样验证. BridgeData V2 每策略 170 次，平均得分 70.6%，部分任务可获半分；RT-2-X 为 50.6%，但在语义泛化子集上更好。不能外推到任意新本体。

EAI-3 / 视觉运动策略与示范接口

Diffusion Policy

动作接口

动作策略先读 Diffusion Policy，示教学 UMI。UMI 有真实的部署策略，但其采集工具、坐标系与时钟对齐不是另一种动作生成算法。

  • Diffusion Policy — 策略：生成动作序列
  • UMI — 采集与执行接口
文字版运行步骤
  1. 观测历史 (及任务)
  2. 构建条件特征
  3. 生成动作序列
  4. 执行前缀 → 更新观测

反馈与边界. 从噪声轨迹出发反复 scheduler.step，得到预测长度内的动作。predict_action 将输出反归一化，只取从 To−1 开始、长度 n_action_steps 的切片交给执行器，再获取观测。预测长度不等于开环执行长度。

怎样验证. 原论文跨四个操作基准的 12 个任务评测动作策略；不是视频预测基准。动作层面成功并不能证明内部显式模拟了杯子。比较不同方法要固定执行频率和示范分布。

EAI-4 / 轨迹数据、跨本体预训练与适配

Octo

数据与迁移

把数据来源、共享训练和目标本体适配分开。数据格式可互读，不代表动作空间已对齐；跨房间的迁移也不是跨机械臂的迁移。

  • Open X-Embodiment / RT-X — 跨本体数据与配方
  • Octo — 消费这些轨迹的策略
  • DROID — 同机型、多地点对照
文字版运行步骤
  1. 编码语言指令或目标图像及近期机器人观测
  2. 屏蔽缺失输入，用共享 Transformer 提取读出 token
  3. 小型扩散头以读出为条件去噪动作块
  4. 将动作转换到本体接口，执行一段再观测

反馈与边界. 按滚动窗口重新查询策略；块内去噪迭代不读取新的实机观测。新增传感器或动作头的微调在线下进行。

怎样验证. Fig. 4 测预训练已覆盖接口；Table I 约用每域 100 条目标示范微调，每域实测 20 次。

EAI-5 / 足式与人形控制

Rapid Motor Adaptation (RMA)

任务与本体

保留为本体/控制任务入口，而非单一算法。RMA 用历史推断隐环境变量，不能代表人形遥操作与全身模仿。

  • RMA — 四足快速适应
  • HumanPlus — 人形跟踪与模仿
文字版运行步骤
  1. 读取关节、机身倾角、足底接触并保存状态—动作历史
  2. 慢适应器从 50 步历史估计环境潜变量（约 10 Hz）
  3. 基础策略读取当前状态、上次动作及最近潜变量（100 Hz）
  4. 输出 12 个关节角目标，由 PD 控制器转换为力矩

反馈与边界. 每个快周期直接读新状态，不等待慢线程；没有实机摩擦真值，也不在线更新权重。

怎样验证. 15 cm 下台阶为 4/5 次成功；Table II 的三种子、多回合统计是仿真。盲感知无法提前看到落差。

EAI-6 / 导航与移动操作

OK-Robot

任务与本体

区分到达目标与完成物体操作。移动操作可因抓姿或释放失败，即使导航已成功。

  • VLMaps — 地图语义与导航目标
  • OK-Robot — 导航后抓放
文字版运行步骤
  1. 准备：人工扫描带位姿的 RGB-D，建语义与障碍地图
  2. 文本检索目标物，A* 将底盘导航至接近位姿
  3. 现场 RGB-D 上用目标掩模筛选 AnyGrasp 候选，控制手臂抓取
  4. 检索放置地点，导航后按当前分割点云计算释放位置
  5. 移动手臂并松爪

反馈与边界. 抓取与放置重新观测局部场景，但预扫语义地图非持续更新；不是每次失败都自动重试的全局闭环。

怎样验证. 10 个家庭、171 次实验；原始条件 58.5%，清理/消歧后 82.4%，后者改变了测试条件。

EAI-7 / 模拟器与评测协议

CALVIN (long-horizon language control)

实验基础设施

平台定义能发生什么，基准定义怎么算成功，校准检验仿真排序能否代表实机。CALVIN 不独占整个基础设施类别。

  • Habitat — 模拟平台
  • CALVIN — 任务链与判据
  • SIMPLER — 配对仿真/实机校准
文字版运行步骤
  1. 从初始场景取可行的五项任务链
  2. 当前指令和传感器观测送入策略
  3. 被测策略输出机械臂与夹爪动作
  4. 仿真器执行并返回新观测与状态
  5. 任务判据决定继续、换指令或结束计分

反馈与边界. 下一步读新观测；成功才推进指令，超时截断。评测不更新策略。

怎样验证. 1,000 条可行五项链；前缀成功率与平均链长不同，须注明训练/测试场景和传感器。这不是真机验证。

EAI-8 / 强化学习后训练

SERL (real-world online training)

学习环节

在线学习与“后训练已有大模型”不互为定义。SERL 适合讲 actor、回放与异步更新；RECAP 算法 1 展示如何用经验和纠正改进已有策略。

  • SERL — 实机在线 RL 系统
  • RECAP / π*0.6 — 已有 VLA 的经验后训练
文字版运行步骤
  1. 腕部图像与机器人状态
  2. actor 策略输出末端目标
  3. 底层控制器跟踪目标，真机返回新观测
  4. 任务奖励与转移写入在线回放
  5. 学习器将回放与示范混采，更新策略及价值网络

反馈与边界. 机器人持续向 actor 提供观测，异步学习器周期性回传权重。非想象 rollout；原 SERL 不要求每步人工纠正。

怎样验证. 三项 Franka 任务各测 100 次；20 条示范加在线交互对比 100 条示范的 BC，不能据此断言两者真实成本相同。
